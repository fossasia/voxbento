The Voxbento REST API gives you programmatic control over booths and events, lets you query live booth state, and surfaces the WHIP and WHEP stream URLs your interpreter and listener clients need. Whether you're building an event platform integration, a custom booth dashboard, or an automated provisioning script, every operation described in this guide is available over plain HTTPS with JSON.

## Base URL

All API requests for Voxbento services target the official `voxbento.com` domain. 

```text
https://voxbento.com
```

Every REST endpoint is prefixed with `/api/`. For example, the token endpoint is reachable at `https://voxbento.com/api/auth/token`.

## Content Type

All request bodies must be sent as `application/json`, and all successful responses are returned as `application/json`. Make sure to include the `Content-Type: application/json` header on any request that carries a body.

## Available Endpoints

The tables below list every REST and WebSocket endpoint exposed by the Voxbento API. Endpoints marked **Bearer** require an `Authorization: Bearer {token}` header — see [Authentication](./authentication.mdx) for details.

### REST Endpoints

| Endpoint | Method | Auth | Description |
| --- | --- | --- | --- |
| `/api/auth/token` | `POST` | Open | Issue a legacy bearer JWT |
| `/api/booth/{booth_id}/state` | `GET` | Bearer | Get booth state (legacy, no event scope) |
| `/api/booth/{booth_id}/whip-url` | `GET` | Bearer | Get WHIP URL for the active interpreter |
| `/api/events/{event_slug}/booths` | `POST` | Bearer | Create an in-memory booth for an event |
| `/api/events/{event_slug}/booths` | `GET` | Bearer | List all booths for an event |
| `/api/events/{event_slug}/booths/{language_code}/state` | `GET` | Bearer | Get event-scoped booth state |
| `/api/events/{event_slug}/booths/{language_code}/whip-url` | `GET` | Bearer | Get event-scoped WHIP URL |
| `/api/interpreter/status/{channel_id}` | `GET` | Open | Check MediaMTX stream reachability |
| `/api/v1/events/{event_slug}` | `GET` | Bearer (OAuth access token with `events:read` scope) | Retrieve event details via REST API v1 |
| `/api/v1/events/{event_slug}/rooms` | `GET` | Bearer | List event rooms and configurations |
| `/api/v1/events/{event_slug}/rooms/{room_id}/booths` | `GET` | Bearer | List booths configured for a specific room |
| `/api/v1/events/{event_slug}/rooms/{room_id}/status` | `GET` | Bearer | Operational status of room media and transcription |
| `/api/v1/events/{event_slug}/rooms/{room_id}/booths/{language_code}/transcripts/export` | `GET` | Bearer (OAuth access token with `transcripts:read` scope) | Export a booth's transcript segments in chronological order; add `?target_lang=xx` for its translations |

### WebSocket Endpoints

| Endpoint | Auth | Description |
| --- | --- | --- |
| `/ws/booth/{booth_id}` | Optional JWT via `?token=` query parameter or session cookie | Real-time booth coordination — join, leave, chat, handoffs, and publish tickets |
| `/ws/captions/{booth_id}` | Protected (`BOOTH_ACCESS_TOKEN` / session token or cookie in production; open in dev when unset) | Live caption and translated caption feed for listeners |
| `/ws/tts/{room_id}/{language_code}/{booth_id}` | Pre-authorized (token or join code) | Direct-push synthetic audio stream with framed binary bundle messages |

## The Captions WebSocket Broadcast

The `/ws/captions/{booth_id}` endpoint delivers live AI transcription and translated caption events. In production deployments where `BOOTH_ACCESS_TOKEN` is configured, connections are authenticated via `resolve_ws_auth`, accepting a participant/listener JWT via `?token=` or a session cookie (`session_token` / `user_token`). In local development with `BOOTH_ACCESS_TOKEN` unset, listeners can connect without credentials.

### Subscribing to Captions
Listeners open a WebSocket connection to the endpoint. The server immediately begins pushing messages as they are generated by the active transcription provider or translation worker.

```json
{
  "type": "caption",
  "text": "The quick brown fox...",
  "status": "partial",
  "provider": "openai"
}
```

The server also broadcasts `booth:state` over this connection, so the listener UI can display when the interpreter goes offline or changes.

## Health Check

Before making API calls you can verify that both the Voxbento portal and the underlying MediaMTX media server are reachable by hitting the health endpoint. This endpoint requires no authentication.

```text
GET /healthz
```

A healthy response looks like this:

```json
{
  "ok": true,
  "server": "fastapi",
  "mediamtx_ok": true
}
```

If `mediamtx_ok` is `false`, interpreter ingest and listener playback will be unavailable even if the portal itself is running.

:::info
Use `mediamtx_ok` to determine whether the media server is reachable before starting a stream. If it is `false`, the underlying media services may be unavailable.
:::
