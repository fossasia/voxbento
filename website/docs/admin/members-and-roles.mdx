Voxbento uses a role-based permission system that lets you grant each participant exactly the access they need — no more, no less. Roles are scoped per event, so the same person can be an interpreter at one conference and a listener at another. This guide covers the full role hierarchy, how to assign roles at both the event and booth level, and how to manage user account flags.

## Role Hierarchy

Voxbento defines five roles, ordered from most to least privileged:

```text
super_admin > event_owner > room_coordinator > interpreter > support > listener
```

| Role | Description |
| --- | --- |
| **super\_admin** | Site-wide admin access. Can manage all events, users, and system settings. |
| **event\_owner** | Full control over a specific event — manages rooms, booths, generates tokens, and can go live. |
| **room\_coordinator** | Can go live, reassign the active interpreter, and manage handoffs during a session across a room. |
| **interpreter** | Can go live (publish audio via WHIP) when designated active and participate in booth chat. |
| **support** | View-only access to booth status and monitoring feeds without chat or broadcast privileges. |
| **listener** | Attendee role: connects to public audio streams via WHEP or HLS and receives live captions. |

## Permission Matrix

The table below shows which actions each role can perform within a booth or event:

| Permission | super\_admin | event\_owner | room\_coordinator | interpreter | support | listener |
| --- | :-: | :-: | :-: | :-: | :-: | :-: |
| Go Live (publish audio) | ✓ | ✓ | ✓ | ✓ (active only) | — | — |
| Set Active Interpreter | ✓ | ✓ | ✓ | — | — | — |
| Chat | ✓ | ✓ | ✓ | ✓ | — | — |
| Manage Booths | ✓ | ✓ | — | — | — | — |
| Manage Events | ✓ | — | — | — | — | — |

## Role Scopes and Boundaries

Permissions in Voxbento are scoped according to privilege level:
- **`super_admin`**: Site-wide platform authority (`User.is_admin = True`), with global access across all events and settings.
- **`event_owner`**: Event-scoped (`EventMembership`), granting administrative and configuration control across all rooms and booths within that specific event.
- **`room_coordinator`**: Room-scoped (`RoomMembership`), conferring operational authority in Mission Control and floor source controls for assigned rooms.
- **`interpreter` / `support`**: Booth-scoped (`BoothMembership`) or assigned across rooms/events.

Cross-event permission isolation applies to event- and room-scoped assignments: an organizer or interpreter assigned to `pycon2026` has no special permissions on any other event. This design lets you safely reuse the same user accounts across multiple events without permission bleed.

## Assigning Event-Level Roles

Use event-level role assignment when a user needs co-ownership of an entire event.

### Open the admin or workspace panel

Sign in at `/login` and navigate to your event.
### Open the event

Click the event you want to manage.
### Go to Manage Members

Click **Manage Members** on the event detail page (`/workspace/events/{event_id}/members/` or `/admin/...`).
### Enter the user's email

In the **Assign Member** form, type the registered email address of the user you want to add.
### Assign Role

Click **Assign Role**. The user is granted `event_owner` permissions for this event and can manage its rooms and booths.

## Assigning Room-Level Roles

For users who manage handoffs and oversee operations across multiple language channels in a single physical room, assign them at the room level.

### Navigate to the room

From the admin panel, go to your event → **Rooms** → open the target room.
  ### Scroll to Assigned Room Coordinators

Find the **Assigned Room Coordinators** section on the room detail page.
  ### Enter the user's email

Under **Assign Coordinator**, type the registered email address of the user.
  ### Select a role

Choose `room_coordinator` from the dropdown.
  ### Submit

Click **Assign**. When the room_coordinator logs in, they will see a link to monitor this specific room.

## Assigning Booth-Level Roles

For stricter access control, you can assign a user to a specific booth rather than the whole event. This is useful when an interpreter should only access one language channel and should not see other booths.

### Navigate to the booth

From the admin panel, go to your event → **Rooms** → select a room → **Booths** → open the target booth.
  ### Scroll to Assigned Members

Find the **Assigned Members** section on the booth detail page.
  ### Enter the user's email

Under **Assign Member**, type the registered email address of the user.
  ### Select a role

Choose a role from the dropdown — typically `interpreter` for booth-level assignments.
  ### Submit

Click **Assign Member**. When the interpreter logs in, they will see an **Open Booth** button on their home dashboard that links directly to this booth.

## Removing a Role

To remove a role from a user at either the event or booth level:

1. Open the **Members** section of the relevant event or booth.
2. Find the user in the list.
3. Click **Remove** next to their name.

The change takes effect immediately. The user loses the associated permissions on their next action or page load.

## User Admin Flags

The **Users** page at `/admin/users/` lists all registered accounts and exposes in-place access switches:

- **Hosting access**: Allows the user to create new events and become an event owner.
- **Admin**: Grants site-wide super administrator permissions (guarded against self-demotion or removal of the last admin).
- **Active / Deactivated**: Disables login access immediately without deleting the account.
- **Email verified**: Toggles whether the account's email has completed verification, which is required for password sign-in.
