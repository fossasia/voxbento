VoxBento has four roles. Each one is defined once in `portal/roles.py`, and every page, booth action and API check follows that definition, so changing what a role may do means changing it in one place.

## The four roles

| Role | Who it is for | Can be given |
| --- | --- | --- |
| **Admin** | People who run the VoxBento platform. | Account-wide (from **Admin → Users**) |
| **Event owner** | People who run an event: its rooms, booths, team and keys. | Per event |
| **Room coordinator** | People who run the live session in a room from Mission Control. | Per event, room or booth |
| **Interpreter** | People who interpret in a booth. | Per event or booth |

The word "Admin" means only the platform role. Every other access check is named after the roles it lets in, for example "owner of this event" or "coordinator of this room".

**Hosting access is not a role.** It is an account setting that lets a person create new events; whoever creates an event becomes its Event owner.

**Listening is not a role either.** Anyone with the event link or join code can listen.

## What each role can do

| Action | Admin | Event owner | Room coordinator | Interpreter |
| --- | :-: | :-: | :-: | :-: |
| Manage users, Admins, hosting access and developer apps | ✓ | | | |
| See all events on the platform | ✓ | | | |
| Create new events (also any user with hosting access) | ✓ | | | |
| Edit and delete their event | ✓ | ✓ | | |
| Manage rooms, booths, members and invites in their event | ✓ | ✓ | | |
| Manage AI provider keys and API keys of their event | ✓ | ✓ | | |
| Use Mission Control for their event or rooms | ✓ | ✓ | ✓ | |
| Start and stop floor transcription in their rooms | ✓ | ✓ | ✓ | |
| Choose the active interpreter in a booth | ✓ | ✓ | ✓ | |
| Go live in a booth | ✓ | ✓ | ✓ | ✓ |
| Use the booth chat | ✓ | ✓ | ✓ | ✓ |
| View booths of their event | ✓ | ✓ | ✓ | ✓ |

Admins can take event actions in any event. The Admin area shows other people's events read-only; Admins change an event they don't own only when helping its owners.

Each role can do everything the roles below it can. When a person holds several roles in the same event, for example Interpreter in one booth and Room coordinator of the room, they get the combined permissions of those roles.

Roles are scoped: an Event owner of `pycon2026` has no special permissions in any other event, so the same account can be reused across events safely.

## Apps that create events

When a third-party app (for example the Eventyay plugin) creates an event for an organizer, the organizer becomes its Event owner. The app's developer gets no automatic access; the organizer can add them to the team if they want help.

When a person connects an app to an event, the app gets only what that person may do. An Event owner can allow everything. A Room coordinator (given for the event, a room or a booth) can allow reading the event and running live sessions in their rooms (`rooms:read`, `booths:read`, `sessions:manage`, `sessions:read`, `transcripts:read`, `listeners:provision`), never creating or deleting rooms or booths. The organizer becomes Event owner only when the app's server confirms the connection, not when they click **Allow**.

## Adding someone to the team

Everything about an event's team happens on its **Team** page. Only the event's owners (and Admins) can open it.

### Open the Team page

Sign in at `/login`, open the event from **My events** and click **Team** (`/workspace/events/{event_id}/team/`).

### Enter their email

Under **Add someone**, type the person's email address. They don't need an account yet; VoxBento creates one and emails them a link to sign in.

### Choose a Role and Where

Pick a **Role**. The text under the form explains what it can do. Then choose **Where** it applies: the whole event, one room or one booth. The list only offers places that role can be given (see the table above).

### Click Add to team

The person appears under **People** with their role. Someone who hasn't signed in yet is marked **Hasn't signed in yet**, with a **Resend invitation** button.

A person can hold one role per place and several roles across the event, for example Room coordinator of Main Hall and Interpreter in the Room 2 · Chinese booth. Giving someone a different role at a place where they already have one replaces it.

## Invite links

A booth invite link lets someone join one booth without an account. Create it under **Invite links** on the Team page by choosing the booth, the role (Interpreter or Room coordinator), an optional label and an optional expiry in hours. Anyone with the link can use it, so send it only to the person it is for and **Revoke** it when it is no longer needed.

## Removing a role

1. Open the event's **Team** page.
2. Find the person under **People**. Use the search box or the role filters if the team is large.
3. Click **×** on the role you want to remove and confirm.

Only that role is removed; the person keeps any other roles in the event. An event always keeps at least one Event owner, so add another owner before removing the last one.

The change takes effect immediately. The person loses the associated permissions on their next action or page load.

## User Admin Flags

The **Users** page at `/admin/users/` lists all registered accounts and exposes in-place access switches:

- **Hosting access**: Allows the user to create new events and become an event owner.
- **Admin**: Makes the person an Admin, the platform-wide role (guarded against self-demotion or removal of the last Admin).
- **Active / Deactivated**: Disables login access immediately without deleting the account.
- **Email verified**: Toggles whether the account's email has completed verification, which is required for password sign-in.
